# Agent Rules & Guidelines (Gemini 사투리 봇 프로젝트)

이 파일은 AI 에이전트(저를 포함한 AI 코딩 어시스턴트)가 이 프로젝트에서 작업할 때 반드시 지켜야 할 **행동 지침(Rules)과 제약 사항**을 정의하는 문서입니다.

## 🌐 프로젝트 공통 규칙 (Common Rules)
- **커뮤니케이션 및 작업 방식**: 코드를 대대적으로 변경하거나 구조를 뒤집어야 할 때는 임의로 진행하지 말고, 항상 **실행 계획(Implementation Plan)**을 작성하여 사용자의 승인을 먼저 받으세요.
- **주석 및 문서화**: 복잡한 비즈니스 로직이나 사투리 번역 프롬프트와 같은 핵심 로직에는 왜(Why) 그렇게 구현했는지 명확한 한국어 주석을 남기세요.
- **스스로 검증**: 새 파일이나 기능 구현을 마쳤다면 빌드 오류가 없는지, 테스트가 통과하는지 반드시 **스스로 검증**한 뒤 완료를 보고하세요.

## 🎨 프론트엔드 (Frontend) 규칙
- **언어 및 환경**: JavaScript(React)를 사용하며, 컴포넌트를 기능 단위로 깔끔하게 분리하세요.
- **스타일링**: Vanilla CSS를 사용하며, 인라인 스타일 지양하고 의미 있는 클래스명을 사용하세요.
- **아키텍처 (FSD)**: 반드시 **FSD (Feature-Sliced Design)** 아키텍처 원칙을 준수해야 합니다.
  - 모든 UI/로직 변경은 `app`, `pages`, `widgets`, `features`, `entities`, `shared` 계층의 규칙에 맞게 배치하세요.
  - 하위 계층(예: `shared`)이 상위 계층(예: `features`)을 import 하는 것을 절대 금지합니다.

## ⚙️ 백엔드 (Backend) 규칙
- **언어 및 환경**: Python(FastAPI)을 사용합니다.
- **아키텍처 (클린 아키텍처)**: 반드시 **클린 아키텍처 (Clean Architecture)** 패턴을 유지하세요.
  - 비즈니스 로직(`use_cases`)은 특정 프레임워크나 인프라(DB, 외부 API)에 의존해서는 안 됩니다.
  - 모든 DB 접근과 외부 API(Gemini) 통신은 `interfaces.py`에 정의된 추상화를 통해서만 구현하세요.
- **TDD (테스트 주도 개발)**: 
  - 로직 수정 시 무조건 `tests/unit` 폴더에 **실패하는 단위 테스트 코드를 먼저 작성**한 후 기능 구현을 시작하세요.
  - 테스트 시 실제 DB나 외부 API를 호출하지 않도록 가짜(Mock) 객체를 활용(Mocking)해야 합니다.
